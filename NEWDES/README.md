# Sticker Fight · النسخة المعتمدة للنشر

متجر Laravel بواجهة عربية RTL وإنجليزية LTR، وهوية نهارية وردية هادئة بروح عراقية. `NEWDES` هي النسخة المعتمدة للنشر؛ وجذر تطبيق Laravel المطلوب على الاستضافة هو هذا المجلد، وDocument Root هو `NEWDES/public`. قاعدة البيانات وملف الإعدادات مستقلان عن المتجر السابق.

## المعاينة المحلية

- المتجر: http://localhost:8002
- الإدارة: http://localhost:8002/admin
- بيانات الإدارة المحلية عشوائية ومحفوظة في `.runtime/admin-access.txt` بصلاحية 0600. لا تنشر هذا الملف.
- MySQL محلي: قاعدة `sticker_fight_newdes` ومستخدم مستقل. الإعدادات الحقيقية في `.env` الخاص بهذه النسخة، وليست في المستودع.
- وضع العرض متوقف: `STORE_DEMO_MODE=false`، وعدّ الإضافات الفعلية للسلة مفعّل: `TRACK_CART_ADDITIONS=true`. نقل الكتالوج يحفظ الصور الأصلية وتصنيفاتها وأسعارها وتمييزها؛ ولا ينقل طلبات المتجر السابق أو حساباته أو أسراره.

اعتماد النسخة المحلية بتاريخ 31 أكتوبر 2026: الكتالوج الفعّال 2,229 تصميماً و78 تصنيفاً. أُرشفت طلبات المتصفح الآلية العشرة قبل إزالتها، وحُفظ الطلبان الآخران ونسخهما المثبتة. منتجات العرض وقوالبه خارج الخيارات الفعّالة؛ والقالبان المتاحان يستخدمان اعتماد المالك المسجل في النسخة الأولى، مع بقاء الإصدارات القديمة دون تعديل. أجور التوصيل نُقلت من إعدادات المالك فقط؛ المناطق التي لم تُحدد لها أجرة فعلية تبقى غير مفعلة إلى أن تُضبط من الإدارة.

## التقنيات المختبرة

PHP 8.5.7، Laravel 13.38.0، MySQL، Blade، Vite 7.3.7، JavaScript، ومكتبة SVG.js 3.2.5. التصدير الخادمي يستخدم Chromium عبر Playwright وpdf-lib؛ الخط نفسه Cairo في المحرر والتصدير. `composer.lock` و`package-lock.json` يثبتان الإصدارات المتوافقة، دون إضافة اعتماد برمجي جديد لهذه النسخة.

## تثبيت نسخة جديدة

يتطلب PHP مع pdo_mysql وgd وexif وzip وmbstring وfileinfo، وComposer، وNode وnpm، وMySQL. يلزم Chromium لمحرك التصدير.

```sh
composer install
npm ci
npx playwright install chromium
cp .env.example .env
php artisan key:generate --no-interaction
```

أنشئ قاعدة MySQL ومستخدماً خاصاً بها، واملأ `DB_*` و`APP_URL` و`SESSION_COOKIE` في `.env`. في اللوكال HTTP اجعل `SESSION_SECURE_COOKIE=false`. في النشر HTTPS اجعله true مع `APP_DEBUG=false`. لا تنسخ مفتاح APP_KEY من متجر آخر، ولا تغيّره بعد حفظ الطلبات والتصاميم.

```sh
php artisan migrate --force --no-interaction
php artisan db:seed --force --no-interaction
php artisan sticker:admin
npm run build
```

أمر إنشاء المدير يطلب كلمة المرور بصورة مخفية، ولا يحتوي المشروع على حساب إنتاج افتراضي. للتطوير المحلي فقط يمكن استخدام:

```sh
php artisan sticker:admin --local-access --email=owner@newdes.test --name="Sticker Fight Owner" --no-interaction
```

لبيانات العرض في قاعدة تطوير منفصلة فقط: فعّل `STORE_DEMO_MODE=true` و`TRACK_CART_ADDITIONS=false` ثم نفّذ `php artisan db:seed --class=NewdesDemoSeeder --no-interaction`. هذا الأمر يرفض بيئة production. لا تستخدمه على قاعدة تجارية: يفعّل أسعاراً وتوصيلاً وقوالب تجريبية لأغراض اختبار البرنامج فقط.

## التشغيل

```sh
PORT=8002 bash scripts/start-local.sh
```

السكربت يشغّل العامل والخادم بحد رفع 14M وحد POST ‏18M وذاكرة 512M. يحتاج خادم MySQL متاحاً وفق `.env`. بديل التشغيل المنفصل:

```sh
php -d upload_max_filesize=14M -d post_max_size=18M -d memory_limit=512M artisan serve --host=127.0.0.1 --port=8002 --no-reload
php artisan queue:work --sleep=2 --tries=3 --timeout=210 --no-interaction
```

لـ`NODE_BINARY` و`CHROMIUM_EXECUTABLE` يمكن ضبط مسار صريح إذا لم تكن البرامج في PATH الخاص بعامل الإنتاج. عرض صفحات المعرض لا يحمّل مكتبة المحرر الثقيلة.

## ما هو متصل فعلياً

- المنتجات والتصنيفات والخامات والتشطيبات والأسعار والقوالب والإصدارات، والسلة والطلب كضيف وتتبع الطلب الآمن.
- محرر بثلاث مراحل: اختيار القالب → تخصيص التصميم → المراجعة والطلب. رفع JPG/PNG/WebP حتى 14 MiB، صورة كاملة افتراضياً مع حرية التحريك والتكبير والتصغير والتدوير، عربي وإنجليزي، طبقات وتراجع وإعادة وضبط، حفظ تلقائي واستعادة خاصة.
- تصميم الكتالوج ثابت. طلبه يمر بخيارات القالب والخامة والكمية، ولا يفتح محرر تغيير الرسم.
- التصاميم المهيأة للاسم تتيح كتابة اسم واختيار خط عربي أو إنجليزي تلقائياً حسب اللغة. الإدارة تحدد المكان الافتراضي ولون الاسم وحجمه الأقصى؛ والزبون يحرك الاسم على معاينة البطاقة باللمس أو الماوس. يثبت الموضع المختار في الطلب مع ملفات الخط. للتثبيت الجديد: `php artisan db:seed --class=PersonalizedProductSeeder --force --no-interaction` لإضافة التصميم الأصلي الأول دون تغيير الأسعار العامة أو منتجات المالك.
- تعديل تصميم خاص من السلة يستبدل إصدار البند المحدد. لا يغيّر أي طلب سابق ولا يضيف بنداً مكرراً.
- المنتجات المميزة أولاً في الترتيب الافتراضي، بترتيب يدوي `featured_order`. اختيارات السعر والاسم والأحدث يطبقها المتجر كما اختارها الزبون.
- الأكثر مبيعاً: `popularity_count` يعني عدد السلات المميزة التي أضافت المنتج بنجاح. الاستحقاق من 11. مفتاح فريد لكل منتج ورمز سلة يمنع تكرار العد عند إعادة المحاولة أو تغيير الخيارات والكمية أو الحذف وإعادة الإضافة. تأكيد الطلب يفتح رمز سلة جديداً. الطلب نفسه لا يزيد العداد. إجراءات الموظفين والمنتجات المعلمة تجريبية وبيئات الاختبار مستبعدة.
- المبيعات مؤشر مستقل: الإيراد والكميات من الطلبات المسلّمة فقط، مع فصل حالة التحصيل المالي عن تنفيذ الطلب. لا توجد تقييمات أو مبيعات تجريبية منشورة على أنها حقيقية.
- أجهزة التحكم والكونسول بفئات PlayStation وXbox، واللابتوبات والتابلت وأجهزة أخرى. الموديلات والتوافق وقوالبها من الإدارة. طلبات الأجهزة تمر بعرض سعر ومراجعة للموديل والقص، ولا تُطلب على قالب بطاقة أو بسعر بطاقات افتراضي. إصدار القالب المعتمد، إن توفر، يثبت مع طلب المراجعة؛ القوالب غير المتاحة لا توصف بأنها جاهزة للإنتاج.
- صفحة مشاريع وجملة، شرائح أسعار قابلة للتفعيل حسب الخدمة والمواصفات، وطلب عرض سعر بمقاس وشكل وكمية وخامة وشعار خاص. تظهر المرفقات وحالة المتابعة في إدارة طلبات الأجهزة والستيكرات.
- PDF فعلي وPNG وSVG رسم ومسار قص مستقل وبيان إنتاج وحزمة ZIP لكل بند بطاقة، من النسخة المثبتة في الطلب. فشل التصدير منفصل وقابل لإعادة المحاولة.
- اختيار اختياري لكل تصميم خاص: نشره في «تصاميمكم اللطيفة» أو إبقاؤه خاصاً. الافتراضي لا، ورفض النشر لا يعطل الطلب.
- محتوى عنوان الرئيسية ووصفها وخطوات وصور وفيديو التركيب والأسئلة والسياسات والتواصل قابل للتحرير من الإدارة. الروابط التجارية تبقى فارغة حتى يملأها المالك.
- المحاسبة والمخزون ومهام الفريق وصلاحياته موروثة داخل هذه النسخة ومعزولة بقاعدة البيانات الخاصة بها.

## الإدارة

راجع [دليل الإدارة](docs/ADMIN.md)، [الهوية](docs/BRAND.md)، [قاعدة البيانات](docs/DATABASE.md)، [الإنتاج](docs/PRODUCTION.md)، و[تقرير القبول](docs/ACCEPTANCE.md).

المنتجات من `/admin/manage/products`؛ ضع «تصميم مميز» ورقم ترتيب (الأقل أولاً). للأجهزة اختر قسم المنتج ثم الموديلات التابعة للقسم. أقسام الأجهزة تدعم قسماً رئيسياً وفرعياً ونوع «أجهزة» أو «مشاريع وجملة». لا تسمح المطابقة الخادمية بربط موديل من قسم آخر.

قوالب البطاقات لها إصدارات مستقلة واعتماد عينة فعلية. قوالب الأجهزة أيضاً تتضمن موديل الجهاز وإصداراً وهندسة mm ومرجع عينة. تعديل هندسة إصدار مرتبط بطلب سابق يحتاج إصداراً جديداً. شرائح الجملة تتطلب وصف المقاس والخامة والشروط؛ لا تُحوّل إلى تسعير تلقائي لطلب مختلف في مواصفاته.

## الاختبارات

```sh
php artisan test --compact
npm run build
npm run test:newdes
node scripts/renderer-test.mjs
```

اختبارات PHP تستخدم SQLite في الذاكرة ولا تمس MySQL المحلي. اختبار المتصفح يحتاج تشغيل هذه النسخة التجريبية على localhost:8002 وحسابها المحلي الخاص، ويرفض الكتابة إذا غاب شريط البيانات التجريبية. ينشئ طلبات DEMO، يختبر Chrome وWebKit، ويشغّل Queue ثم يتحقق من تنزيل ملفات الإنتاج. لا يشغّل المتصفح من جلسات المستخدم أو ملفاته الشخصية. نتائج الاختبار وصور الهاتف والكمبيوتر في `.runtime/`.

## النشر والتشغيل المستمر

عند النشر من مستودع GitHub الحالي اجعل مجلد التطبيق `NEWDES` وdocument root هو `NEWDES/public`. نفّذ أوامر Composer وnpm وArtisan من داخل `NEWDES`، حتى لا تشغّل المتجر السابق في جذر المستودع. لا تنشر `.env` أو `.runtime` أو قاعدة بيانات اللوكال أو مرفقات التجربة. `storage/app/private` غير عام؛ لا تنشئ رابطاً عاماً له. ملفات الزبائن تصل فقط بعد التحقق من الجلسة/الصلاحية/رابط الطلب الخاص. صور الكتالوج وسجلات المنتجات والتصنيفات مرفقة بحزمة إصدار GitHub `newdes-2026-10-31`. بعد migrations وتهيئة قاعدة الإنتاج شغّل الأمر أدناه لنقل الكتالوج، دون ملفات الزبائن أو بيانات دخول اللوكال.

بعد نشر الكود: ثبّت الاعتمادات، نفّذ migrations، وابنِ الأصول ثم `php artisan optimize` و`php artisan queue:restart`. شغّل Queue بمدير عمليات دائم؛ `retry_after=240` أكبر من timeout العامل 210. اجعل cron ينفذ `php artisan schedule:run` كل دقيقة. إعدادات Nginx وSupervisor النموذجية ضمن `docs/deployment`؛ غيّر مسار المشروع إلى مسار NEWDES الفعلي.

رفع الكتالوج حتى 4 MiB، والمحرر/مرفقات التسعير حتى 14 MiB. اضبط الاستضافة على `upload_max_filesize=14M` و`post_max_size=18M` على الأقل، وحد حجم طلب Nginx/Apache المناسب. ملف `.user.ini` يعمل فقط إن سمحت به الاستضافة.

النسخ الاحتياطي مشفر بالأمر `sticker:backup`، ويحتاج `BACKUP_PASSWORD` خاصاً خارج الكود وmysqldump متاحاً. فعّله فقط بعد إعداد وجهة نسخ خارج الخادم واختبار `sticker:backup-verify` حسب `artisan list`. الحذف الآلي متوقف افتراضياً؛ راجع `sticker:purge` دون `--force` أولاً. المرفقات المرتبطة بطلبات التسعير محفوظة ولا تُحذف مع تنظيف المسودات.

## قبل استقبال طلبات حقيقية

أنشئ قاعدة إنتاج نظيفة ببيانات المالك، وأوقف `STORE_DEMO_MODE`. ضع الأسعار الفعلية والخامات والتشطيبات وأجور التوصيل وبيانات التواصل والسياسات، ثم اعتمد عينة القوالب والخامة فعلياً قبل تفعيل الطلبات. لا تنقل اعتمادات DEMO إلى الإنتاج. قِس العينة بنسبة 100% دون Fit to Page، وتحقق من موضع الشريحة وفتحات الخلف والقص مع معداتك.

الدفع الفعلي المتاح حالياً عند الاستلام فقط. لا تظهر بوابة إلكترونية أو تكامل Instagram أو WhatsApp آلي غير مربوط. CMYK وICC وPDF/X والحبر الأبيض وتجميع الشيت ليست مفعلة، وتحتاج إعداداً موثقاً واختباراً لدى المطبعة. التصدير الحالي sRGB و300 PPI مع دقة مصادر محسوبة؛ نجاحه لا يثبت خواص الخامة أو اعتماد القص الفعلي.

## نقل كتالوج NEWDES من GitHub

حزمة الإصدار `newdes-2026-10-31` تضم ٢٬٢٤٢ تصميماً فعلياً و٧٩ تصنيفاً، بما فيها التصاميم التي تقبل الاسم ومكانه اليدوي. افتح الطرفية من داخل `NEWDES` وشغّل بعد تثبيت المشروع وmigrations:

```sh
php -d memory_limit=512M artisan sticker:catalog-restore --no-interaction
```

ينزّل الأمر حزمة بحجم يقارب ٢ غيغابايت، ويتحقق من SHA-256 وكل صورة، ثم يستورد المنتجات والصور والتصنيفات والأقسام والموديلات وترتيب المميز وإعداد الاسم. يمكن تنزيل ZIP من الإصدار ونقله إلى مجلد خاص بالخادم واستخدام `--archive=/private/path/sticker-fight-newdes-catalog-2026-10-31.zip` بدل التنزيل الآلي. يلزم نحو ٧ غيغابايت مساحة مؤقتة. إعادة التشغيل لا تكرر التصاميم ولا تستبدل تعديلات الإدارة أو تعيد المحذوف؛ لا يحذف الأمر كتالوج الاستضافة الموجود.

الحزمة كتالوج فقط: لا تنقل الطلبات والعملاء والمستخدمين وملفاتهم، ولا عدادات الإضافة للسلة أو المبيعات أو إعدادات التوصيل والتحصيل. أسعار المنتجات الخاصة محفوظة، والأسعار العامة والخامات والقوالب المعتمدة تضبطها الإدارة على قاعدة الإنتاج. تبقى الطباعة والطلبات متوقفة حتى تكميل إعدادات المتجر. ملفات ثمانية الخاصة تنقلها بصورة منفصلة وفق `docs/OPERATIONS.md`.

لإنشاء حزمة جديدة من كتالوج تملكه لاحقاً: `php artisan sticker:catalog-export /private/path/new-catalog.zip --no-interaction`. حدّث بصمة الحزمة ورابطها في `config/catalog.php` قبل نشرها؛ لا ترفع قاعدة البيانات الكاملة إلى GitHub.
