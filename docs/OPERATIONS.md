# التشغيل والاستعادة

## النشر

نطاق واستضافة وTLS وإعداد DNS وSMTP أو خدمات الرسائل لم تُوفَّر. لا يوجد نشر عام أو اتصال وهمي ببوابة دفع أو Instagram API. المشروع قابل للنشر على PHP-FPM/MySQL مع Node وChromium عاملين على الخادم نفسه. يمكن فصل عامل التصدير لاحقاً، بشرط وصوله إلى التخزين الخاص والخطوط والنسخ المثبتة نفسها.

- انسخ المصدر وملفات البناء دون `.env` أو `.env.qa` أو `.runtime` أو بيانات الاختبار.
- اضبط بيئة الإنتاج ومستخدم قاعدة خاصاً بالمتجر، وأنشئ مفتاحاً جديداً للتثبيت الجديد. لا تغيّر `APP_KEY` في نظام قائم بلا خطة لترحيل الجلسات وروابط المتابعة ونسخ البيئة.
- ثبّت الاعتماديات، وشغّل migrations وSeeder. الـSeeder لا يعيد ضبط إعدادات يغيّرها المالك.
- اضبط الأذونات وPHP-FPM وTLS وSupervisor وcron. أبق الجذر `public/` فقط، والتخزين الخاص غير مرتبط بمجلد عام.
- راجع سياسة النسخ والاحتفاظ والخامات والقوالب والأسعار والتوصيل، وجرّب طلب قبول في staging منفصل قبل فتح المتجر.
- بعد كل نشر اختبر العربية ورفع صورة وحفظها وتصدير ملف، ثم أعد تشغيل Queue. لا تغير الخطوط أو محرك Chromium دون مقارنة إنتاجية.

## مراقبة التصدير

تظهر حالة مستقلة لكل بند: انتظار، معالجة، جاهز، فشل، أو انتهاء احتفاظ. مهلة المهمة 200 ثانية، والعامل 210، وإعادة الحجز 240. لا تشغّل عدداً كبيراً من عمال Chromium قبل قياس الذاكرة على صورك الفعلية. الفشل يُسجل في `export_runs` وسجل الخادم، ولا يُعرض مسار أو stack trace للزبون.

إن فشل عامل أو انقطع، راجع `failed_jobs` وسجل العامل، ثم أعد المحاولة من الطلب. المصدر هو snapshot الطلب والأصول المنسوخة وبصماتها. لا تعتمد على أحدث مسودة للزبون. لا تجعل إشعار WhatsApp أو البريد مخزناً وحيداً للملفات.

## النسخ الاحتياطي

يولد `sticker:backup` ZIP مشفراً يشمل dump بـ`--single-transaction --set-gtid-purged=OFF --no-tablespaces` والأصول وملف البيئة، مع SHA-256. كلمة مرور النسخ في البيئة ولا تمرر كوسيط shell. افصل صلاحية قراءة النسخ عن حسابات الموظفين. لا تشارك النسخة عبر رابط عام؛ تحتوي بيانات عملاء وأسراراً مشفّرة.

تفعيل الجدولة اختياري. احتفظ بنسخة خارج الخادم وكلمة مرور مستقلة في مكان آمن. لا يكفي وجود ZIP؛ نفذ `sticker:backup-verify` واختبار استعادة دوري في بيئة معزولة. في أثناء النسخ لا تغيّر بنية الجداول، ولا تشغّل حذف الاحتفاظ بالتزامن مع النسخ. عند إجراء صيانة كبيرة، أوقف قبول الطلبات والعمال حتى تثبيت النسخة.

## الاستعادة

1. جهّز قاعدة وتخزيناً معزولين، وضع النسخة في مجلد خاص محدود الصلاحيات.
2. تحقّق من كلمة المرور والبصمات بـ`sticker:backup-verify` قبل فكها. استخدم أداة تدعم ZIP AES-256؛ بعض أدوات ZIP الافتراضية لا تدعمه.
3. فك `database.sql` و`private/` و`environment.txt` في مجلد صيانة خاص. لا تفكها داخل `public/`.
4. استورد SQL إلى قاعدة جديدة باستخدام بيانات اتصال خاصة بها؛ لا تستبدل قاعدة الإنتاج مباشرة. أعد أصول `private/` إلى جذر التخزين الخاص المطابق.
5. استخدم نسخة الكود وملفات القفل والخطوط الموافقة للنسخة، وراجع إعدادات البيئة. يتطلب فك الجلسات ومتابعة الطلبات المفتاح الأصلي. لا تسجل أسرار البيئة في الأوامر أو التذاكر.
6. قارن أعداد الطلبات والبنود والتصاميم والقوالب وملفات الإنتاج، وافتح طلباً وتحقق من بصمات أصوله ومعاينته. طبق سياسة الاحتفاظ قبل إعادة فتح البيانات القديمة.
7. جرّب تصديراً وتنزيل ZIP وحالة طلب، ثم حوّل إعداد التطبيق إلى القاعدة المستعادة، وأعد تشغيل العمال وافتح الطلبات بعد المراجعة.

نفذ المشروع اختباراً فعلياً: فك النسخة المشفّرة، واستورد SQL إلى قاعدة MySQL مؤقتة، وقارن ستة جداول محورية، ثم حذف قاعدة الاستعادة المؤقتة. لم يستبدل بيانات المتجر الأساسية.

## فصل الزوار على الجهاز المشترك

فتح `/editor` يبدأ بتصميم فارغ، دون رسالة مسودة معلقة أو عرض تصميم الزيارة السابقة تلقائياً. عند انتقال الجهاز إلى شخص آخر، يستخدم زر «مساحة زائر جديدة» في المحرر. الإجراء محمي بـCSRF، وينهي الجلسة والحساب الحالي إن وجد وينشئ جلسة ضيف جديدة؛ لا يحذف التصاميم أو الملفات أو السلة القديمة. العودة إليها تتطلب الجلسة المصرح لها أو رابط الاستعادة الخاص أو الحساب المرتبط.

المتصفح لا يستطيع التعرف إلى تغيّر الشخص وحده؛ إبقاء الجلسة نفسها يعني إبقاء الزيارة نفسها. لذلك زر الزيارة الجديدة هو الإشارة الصريحة للفصل على الجهاز المشترك. تبقى استعادة المسودة داخل الزيارة الحالية باختيار «استعادة مسودتي بهذه الزيارة»، وتبقى استعادة تعديلات التصميم المفتوح محصورة بمساحته.

نسخ المتصفح المحلية مقيدة بمساحة مشتقة من جلسة الضيف، ولا تُقرأ مفاتيح التخزين القديمة غير المقيدة بزائر. يرفض الخادم طلبات تبويب قديم يحمل مساحة مختلفة عن الجلسة الحالية. HTML المخصص يستخدم `private, no-store`؛ وصور الكتالوج العامة لا تبدأ جلسة ولا ترسل ملفات ارتباط، مع بقاء كاش الصور العامة متاحاً. صور الزبائن الخاصة لا تستخدم مسار الكتالوج العام.

## الصيانة والخصوصية

تسجيل الخروج يُبطل جلسة المتصفح. لا تسجل query strings أو مسارات الاستعادة الحساسة في تحليلات عامة. نموذج Nginx يعطل access log للمسارات الخاصة. احتفظ بسجلات الأخطاء بصلاحيات خاصة ودورة تدوير مناسبة؛ قد تحتوي سياقاً فنياً داخلياً.

الحذف الافتراضي غير مفعّل. عاين الأعداد ثم فعّل السياسة المعتمدة. انتهاء احتفاظ الطلب يحذف أصوله وملفات الإنتاج والنصوص القديمة ويحجب بيانات الاتصال التفصيلية، مع بقاء المبيعات والمحافظة والتحصيل. النسخ الاحتياطية لها مدة مستقلة. لا تعرض سياسة غير معتمدة كحقيقة للزبون.

لا توجد analytics أو SMTP أو WhatsApp أو تحصيل إلكتروني مفعّل. لا ترسل الصور أو النصوص أو أسماء العملاء إلى أداة قياس. إذا رُبطت تكاملات مستقبلية فاختبر الأحداث دون هذه البيانات، وفعّلها فقط بإعدادات حقيقية.
