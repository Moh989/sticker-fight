# STICKER FIGHT — Custom Card Skins

متجر Laravel فعلي بالعربية والإنجليزية، مع MySQL، ومحرر SVG، وحفظ الضيف، وسلة وطلب بالدفع عند الاستلام، ولوحة إدارة، وتصدير إنتاج عبر Queue. الاسم والنصوص والألوان المعتمدة محفوظة. لا توجد أسعار تجارية أو بيانات تواصل مفترضة، والقوالب الأولية تجريبية وغير قابلة للطلب حتى اعتمادها.

## فتح النسخة الحالية على هذا الجهاز

```sh
cd /Users/photoshop/stickers
./scripts/start-local.sh
```

المتجر: http://127.0.0.1:8000 — الإدارة: http://127.0.0.1:8000/admin

بيانات المدير المحلي العشوائية موجودة في `.runtime/admin-access.txt` بصلاحية `0600`. هذا حساب تطوير محلي، وليس بيانات مدير افتراضية للنشر. قاعدة المتجر المحلية هي `sticker_fight` على MySQL المعزول بالمنفذ `3307`. قاعدة `sticker_fight_qa` وملف `.env.qa` للاختبارات فقط. لا تنقل أياً من `.runtime` أو `.env*` أو قواعد الاختبار إلى الإنتاج.

يضبط سكربت التشغيل حد رفع الصور محلياً على 14 MB وحجم الطلب على 18 MB والذاكرة على 512 MB، دون تعديل إعداد PHP العام للجهاز. أعد تشغيل السكربت بعد تغيير `.env` أو إعدادات PHP المحلية.

## تثبيت مستقل

النسخة التي تم فحصها: PHP 8.5.7، Laravel 13.38.0، MySQL 9.7.1، Node 24.16.0. الإصدارات الدقيقة لباقي الاعتماديات في `composer.lock` و`package-lock.json`. استخدم إصدارات PHP وMySQL المدعومة على استضافتك، وتحقق من متطلبات ملفات القفل قبل التثبيت. لا تُعتبر نسخة MySQL أخرى مختبرة فعلياً لمجرد توافق صياغة migrations معها.

تحتاج PHP مع PDO MySQL وGD وEXIF وFileinfo وmbstring وintl وDOM وXML وZip وSodium، وComposer، وNode، وChromium الخاص بـPlaywright. إعداد مبدئي للخادم: `upload_max_filesize=14M` و`post_max_size=18M` و`memory_limit=512M`. المعالجة ترفض الصور التي تتجاوز الذاكرة المتاحة. كل صورة حتى 14 MB و32 مليون بكسل، وحتى 30 طبقة لكل جهة.

1. أنشئ قاعدة MySQL بـ`utf8mb4` ومستخدماً خاصاً محدوداً بقاعدة المتجر.
2. انسخ `.env.example` إلى `.env` واضبط الاتصال و`APP_URL` وبيئة التشغيل. لا تضع أسراراً في الكود.
3. نفّذ:

```sh
composer install --no-dev --optimize-autoloader
php artisan key:generate --no-interaction
npm ci
npm run build
npx playwright install --with-deps chromium
php artisan migrate --seed --force --no-interaction
php artisan sticker:admin
```

أمر المدير يطلب البريد والاسم وكلمة مرور مخفية من 12 حرفاً على الأقل. للأتمتة يدعم `--email` و`--name` و`--password-stdin`؛ لا تمرر كلمة المرور كوسيط ظاهر. لا ينشئ Seeder مستخدمين أو كلمات مرور افتراضية.

`Node` و`playwright` و`pdf-lib` لازمة على خادم الإنتاج، حتى بعد بناء الواجهة. يمكنك إزالة اعتماديات التطوير بعد البناء، لكن لا تحذف كل `node_modules`. إذا كنت تستخدم Chromium مُداراً، اضبط `CHROMIUM_EXECUTABLE` إلى مساره الحقيقي. اختبر نفس نسخة الخطوط والمتصفح في البيئة النهائية.

لاستيراد صور الكتالوج التي أضافها المالك ضمن `sss` وتصنيفاتها على تثبيت جديد:

```sh
php artisan sticker:catalog-import sss --no-interaction
```

الأمر يحفظ أصول الإنتاج في التخزين الخاص وينشئ صور عرض محسنة، ويستخدم الأسعار العامة دون اعتماد خامات أو قوالب أو توصيل تلقائياً. إعادة تشغيله تتجاوز الصور الموجودة حسب بصمتها، وتحافظ على أسماء المنتجات وأسعارها وحالة نشرها التي عدلها المالك. ويمكن تمرير مسار فولدر آخر يحوي فولدراً لكل تصنيف. مستودع GitHub يحتوي المصدر وصور الكتالوج المرفقة فقط؛ قاعدة البيانات وملفات الزبائن والأسرار والنسخ الاحتياطية تبقى خارج Git.

### التصاميم المرفقة بإصدار GitHub

حزمة مجموعة الكتالوج المرخصة (2,229 تصميماً مع تصنيفاتها) موجودة ضمن [GitHub Release — catalog-2026-10-26](https://github.com/Moh989/sticker-fight/releases/tag/catalog-2026-10-26). حجم ZIP نحو 1.8 GiB، وملف SHA-256 مرفق به. مستودع الكود لا يحتوي قواعد البيانات أو ملفات الزبائن؛ حزمة الإصدار تحتوي صور الكتالوج المرخصة وبيانها فقط.

بعد سحب التحديث وبناء الواجهة، شغّل على الاستضافة:

```sh
php artisan migrate --force --no-interaction
php artisan db:seed --class=ProductSectionSeeder --no-interaction
php artisan db:seed --class=StockItemSeeder --no-interaction
php -d memory_limit=512M artisan sticker:catalog-install --no-interaction
php artisan optimize
php artisan queue:restart
```

الأمر ينزّل الحزمة عبر HTTPS، ويتحقق من SHA-256 ومحتويات ZIP وبصمات ملفات التخزين المؤقت، ثم يستورد التصاميم إلى التخزين الخاص وقاعدة بيانات الاستضافة. إعادة تشغيله تتجاوز المصادر الموجودة وتحافظ على أسعار وأسماء وحالات المنتجات القديمة التي أمكن مطابقتها؛ القوالب والخامات والأسعار والتوصيل والتحصيل وحسابات المستخدمين تبقى وفق إعدادات قاعدة الاستضافة. يبقى 7 من ملفات المصدر قيد المراجعة إذا لم يكن لها بديل مناسب. إذا منع الخادم الاتصال بـGitHub، نزّل ملف ZIP المرفق بالإصدار وارفعه إلى مجلد خاص ثم استخدم:

```sh
php -d memory_limit=512M artisan sticker:catalog-install --archive=/private/path/cucu-covers-catalog-2026-10-26.zip --no-interaction
```

يلزم امتداد PHP ZipArchive ومساحة كافية للحزمة واستخراج الصور وتوليد أصول الكتالوج (وفر 7 GiB حرة على الأقل). استيراد كامل المجموعة قد يستغرق عدة دقائق. يجب تنفيذ أوامر النشر من جلسة SSH أو Terminal الاستضافة التي تسمح باستمرار العملية. النشر من GitHub وحده لا ينقل محتوى قاعدة البيانات.

4. وجّه جذر الويب إلى `public/` فقط، وامنح PHP والـQueue صلاحية الكتابة إلى `storage/` و`bootstrap/cache/`. لا تنشئ رابطاً عاماً للتخزين الخاص. أعد كل النطاق إلى HTTPS قبل تشغيل الطلبات، مع `APP_DEBUG=false` و`SESSION_SECURE_COOKIE=true`.
5. ملفات Nginx وSupervisor النموذجية في `docs/deployment/`، وتحتاج مسارات ونطاقاً وPHP-FPM وTLS فعليين من المالك.

## Queue وScheduler

```sh
php artisan queue:work --sleep=2 --tries=3 --timeout=210
php artisan schedule:run
```

شغّل `schedule:run` كل دقيقة عبر cron. مهلة إعادة حجز المهمة `DB_QUEUE_RETRY_AFTER=240`، وهي أكبر من مهلة العامل. بعد تحديث الكود:

```sh
php artisan optimize
php artisan queue:restart
```

التصدير مستقل عن حالة الطلب؛ نجاح الملف لا يجيز الطباعة تلقائياً. الفشل يبقى ظاهراً، مع سجل تشغيل وإعادة محاولة من الإدارة. تبدأ الطباعة فقط بعد اعتماد الطلب ووجود ملفات جاهزة.

## تفعيل المتجر

راجع [دليل الإدارة](docs/ADMIN.md). أضف الأسعار والخامات والتشطيبات والتوصيل والسياسات وقنوات التواصل. اعتمد قوالب الإنتاج بعد عينة مطبوعة فعلية بالحجم الكامل، ثم فعّل استقبال الطلبات. البيانات الأولية تنشئ جميع المحافظات ومنها محافظات إقليم كردستان وحلبجة، مع قابلية الإضافة والتعديل دون عدد ثابت في الكود. جميع أجور التوصيل غير مفعّلة إلى أن يضبطها المالك.

التصاميم الجاهزة لها صفحة خيارات شراء مستقلة: الرسم ثابت ويُنشأ خادمياً من أصل الكتالوج؛ يختار الزبون الجهات والقالب والخامة والتشطيب والكمية ثم يضيف للسلة. محرر التخصيص مخصص لصور الزبون ونصوصه، ولا يفتح التصاميم الجاهزة للتعديل.

الكمية هي عدد وحدات المنتج/البطاقات: في خيار الوجهين تنتج كمية مستقلة من كل جهة، أي ملصقان لكل وحدة، وليست طباعة على جانبي ملصق واحد.

## ملفات الإنتاج

[عينة الإنتاج](samples/production/) تضم وجهاً شفافاً غير مطبوع ووجهاً مطبوعاً، ومسارات قص، وPDF وPNG وبياناً وبيانات التصميم. العينة هندسية غير معتمدة للمطبعة. راجع [تفاصيل الإنتاج](docs/PRODUCTION.md).

المحرك الحالي ينتج sRGB PDF وPNG شفافاً وSVG Vector للقص. لا يدّعي CMYK أو PDF/X أو ICC أو حبراً أبيض أو توافق معدات لم يُختبر. هذه الإعدادات تُرفض إذا أُدخلت يدوياً دون دعم.

## النسخ الاحتياطي والاحتفاظ

ضع `BACKUP_PASSWORD` عشوائياً قوياً من 16 حرفاً على الأقل في البيئة، واحفظ نسخة منه خارج الخادم. ثم:

```sh
php artisan sticker:backup
php artisan sticker:backup-verify /absolute/path/to/backup.zip
```

الحزمة مشفّرة بـAES-256 وتحتوي قاعدة البيانات والتخزين الخاص وملف البيئة وبصمات SHA-256. لا يحتوي dump على إعدادات GTID عامة. يدعم الأمر MySQL؛ لا يستخدم كلمة مرور MySQL كوسيط في سطر الأوامر. التفعيل المجدول عبر `BACKUP_ENABLED=true`، والنسخ القديمة تحذف بعد `BACKUP_RETENTION_DAYS`، افتراضياً 30 يوماً. نقل النسخ إلى وجهة خارجية مسؤولية إعداد الاستضافة؛ لا توجد وجهة خارجية مختلقة.

```sh
php artisan sticker:purge
php artisan sticker:purge --orders
```

الأمران أعلاه للمعاينة فقط. `--force` يطبّق الحذف. `DESIGN_RETENTION_DAYS` افتراضياً 90 يوماً للمسودات والأصول غير المستخدمة، مع حماية المراجع الموجودة في السلال والطلبات. بإضافة `--orders --force` تطبق `ORDER_RETENTION_DAYS`، افتراضياً 730 يوماً، على الطلبات المسلّمة/الملغاة/المرتجعة: تحذف ملفاتها وصورها ونصوص تصميمها القديمة، وتُحجب تفاصيل التواصل والعنوان، وتبقى المجاميع والمحافظة وسجل التحصيل. تحفظ المسودات الحديثة أو المراجع المستخدمة في طلب حديث. التفعيل التلقائي يتطلب `PURGE_ENABLED=true`، وحذف ملفات الطلبات يتطلب أيضاً `PURGE_ORDER_FILES=true`.

هذه إعدادات تقنية وليست سياسة تجارية منشورة. يعتمد المالك نصوص الاحتفاظ والخصوصية قبل النشر. النسخ الاحتياطية تنتهي وفق مدتها المستقلة؛ أعد تطبيق الاحتفاظ بعد أي استعادة. راجع [تشغيل النظام والاستعادة](docs/OPERATIONS.md).

## الفحص

```sh
php artisan test
npm run test:render
```

يدعم المتجر ولوحة الإدارة زر «ليلي / نهاري» مع حفظ التفضيل لهذا المتصفح، والليلي هو الافتراضي. ألوان الصور والتصميم وملفات الطباعة مستقلة عن مظهر الواجهة. يمكن فحص النمطين بأمر `node scripts/theme-test.mjs` بعد تشغيل بيئة QA.

اختبارات المتصفح تستخدم قاعدة اختبار مستقلة، ولا تُفعِّل أسعاراً أو قوالب في قاعدة المتجر. راجع [تقرير القبول](docs/ACCEPTANCE.md) لإعادة تشغيلها وحدود ما تم فحصه. `scripts/qa-database.php` مخصص لهذا الجهاز وMySQL المعزول، وليس سكربت نشر.
